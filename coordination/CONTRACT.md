# Coordination v1 implementation contract

One project, four stable slots: vps, hermes, vscode, codex-desktop. Public definition and private runtime state stay separate. This document fixes interfaces for parallel implementers. Root owns catalogue generation and final integration; do not change interfaces without notifying root.

## Catalogue (docs/roadmap/catalog.json)

Object {schemaVersion:1, project:'hampton', slots:[{id,name,area}], tasks:[original checklist fields plus assignedSlot], units:[Unit]}. No self-referential commit SHA; the coordinator records the verified Git SHA on import.

Unit: {id, parentTaskId, title, preferredSlot, priority:number, kind:'development'|'research'|'decision', enabled:boolean, reviewRequired:boolean, dependencies:[{unitId,requiredEvidence:'design'|'integrated'|'research_accepted'|'activated'|'decision'}], resources:[{key,mode:'read'|'write'}], acceptance:[string]}. Existing partial/inferred dependencies remain in task metadata. These are not silently promoted to trusted runnable rules. Unreviewed units can be claimed for planning, never for building: reviewRequired is satisfied by a trusted design evidence attestation for that unit, after checking partial/inferred dependencies and exact intended scope. No need to publish a catalogue change just to record that design review. Historical states disabled. Development resources include logical keys and canonical path:<relative path or trailing-slash directory>. Resource conflicts include parent/child paths, same logical key, and any write; two reads compatible. New dynamic file scope is additive only.

## HTTP

GET /v1/board => {protocolVersion:1,revision,serverTime,catalogSha,slots,tasks,units,claims,evidence,release,blockers}. GET never extends a lease. Completed build claims include derived completionCurrent: true only when their saved completion contract matches the current unit contract. A completed claim with completionCurrent:false is historical and does not prevent claiming an explicitly revised enabled unit. Evidence includes derived evidenceCurrent; only current evidence satisfies dependencies or completion. Consumers use these derived fields and server blockers rather than duplicating contract canonicalization.

POST /v1/catalog body {operationId,expectedRevision,sha}: coordinator role only; fetch catalogue from canonical GitHub main verified against provided SHA, never accept client catalogue definitions. Record no secrets. Validate catalogue before storing and reject incompatible changes to units with live/paused/stale claims, including source-contract changes that invalidate evidence required by a reserved build claim.

POST /v1/claims body {operationId,expectedRevision,slot,sessionId,checkoutId,hostId,taskId?,mode:'plan'|'build',baseSha}. Originator identity derives only from verified JWT. Select own resumable claim first; otherwise available own preferred units by priority then id; then available other slots, but never steal from an occupied/stale slot. Distinct task and logical resources checked atomically. Claim response {claim,revision}; claim={id,unitId,slot,actorId,sessionId,checkoutId,hostId,generation,mode,status,resources,baseSha,updatedAt,expiresAt}. One current claim per slot/session/checkout; stale or parked work remains a conflict. mode plan allows reviewing blocked unit, reserves resources, and MUST NOT authorize product code edits. mode build checks enabled, reviewRequired false and dependency evidence.

POST /v1/claims/:id/{renew,scope,pause,resume,handoff,submit,abandon,complete} body {operationId,generation,sessionId,...}. Always enforce owner and generation (handoff coordinator-only, explicitly supplied target authorized identity/slot, saved handoff evidence). renew extends 15-minute lease only while current, not expired. resume of paused claim checks same generation and dependencies if upgrading to build. scope accepts additive resources. submit includes headSha, changedPaths, evidence summary and no out-of-scope path. abandon requires clean:true and no pending work; complete requires trusted evidence. No expired claim auto-release. Stale actor requires explicit coordinator recovery/handoff, increments generation. Human-visible board says stale without mutating generation.

Evidence POST /v1/evidence {operationId,expectedRevision,unitId,kind,reference,sha?}: coordinator role. For integrated validate Git commit belongs to canonical main (do not accept arbitrary sha). For research_accepted/decision/design/activated explicit coordinator attestation reference is recorded as attestation, not fake automated verification. Must not conflate evidence kinds. Every evidence record is stamped by the server with the current unit scopeDefinition; design also saves reviewedResources from the reserved scope (or catalogue minimum when unclaimed). A later contract change preserves the historical evidence and its verification provenance but makes it ineligible for current dependencies/completion. Contract fields are parentTaskId, preferredSlot, kind, dependencies, resources and acceptance; enabled/history state, reviewRequired and priority do not invalidate otherwise matching proof. Missing scope bindings fail closed. Design dependencies additionally require reviewedResources to cover the current source unit minimum. Completing a claim releases code resources but does not fabricate activated evidence.

POST /v1/release/{acquire,renew,finish}: acquire {operationId,claimId,generation,sessionId,sha}; requires submitted own live claim, serializes publication. renew same owner/generation, no auto steal on expiry. finish includes outcome:'published'|'uncertain'|'cancelled', sha, evidence; published verifies canonical main SHA and imports catalogue before releasing; uncertain retains turn until reconciled. No actual push/deploy in server or CLI. CLI preflights Git before release acquire. Coordination is not publication authorization.

Success JSON, conflict HTTP409 {error:{code,message,details?}}, invalid400, auth401/403, configuration/service503. operationId is an idempotency key scoped by authenticated actor, endpoint and body fingerprint. Reusing key for different payload returns409. Missing/revoked generations rejected even for old idempotent commands if they would give a stale session authority. Cap payload size and allowlist names. No secret/stack trace in response.

## Authentication / deployment

Worker validates Cloudflare Access JWT via jose (existing dependency): issuer, audience, algorithm, expiration; do not trust headers without verification. Configuration ACCESS_TEAM_DOMAIN, ACCESS_AUD, TEAM_IDENTITIES_JSON maps verified service common_name/sub to {actorId,slots,role:'executor'|'coordinator'}, human email to role viewer. Missing/invalid config fail closed. Human viewer is read-only. No dev auth bypass in production Worker. Local tests use signed test JWT and local JWKS or direct DO test RPC. Static assets served only after authentication, same origin; backend paths never fall through assets. Do not use HERMES_KEY/business admins/DB. Worker workers_dev=false until configured deliberately. No new network permissions or secrets installed this task.

## Client

scripts/avanzar-team.mjs exports helpers for tests and has CLI: init, status, claim, renew, watch, scope, pause, resume, handoff, accept-handoff, submit, abandon, complete, evidence, catalog, release. Config private git-dir/avanzar-team.json includes {endpoint,slot,sessionId,hostId,checkoutId}; sessions and pending operation IDs stored next to it atomically. Read credentials ONLY environment CF_ACCESS_CLIENT_ID,CF_ACCESS_CLIENT_SECRET or an explicit private credential file outside tracked tree; never command-line values, printing, localStorage. HTTPS required, HTTP only loopback for fixtures. Never follow redirect forwarding credentials. Commands preserve wrappers via normal git executable. init validates root/canonical origin using existing checker; do not edit .git config/hooks or commit. claim/build and release gate current Git state; parked changes not silently moved. scope paths normalized; submit uses git diff across baseSha..HEAD plus working/staged/untracked paths. Private session id stable across invocation. Status/claim include catalog revision; reuse pending operationId on retry. watch foreground renewal60s, stops on signals/failure; no installed daemon. Offline cannot grant work or publish. Outputs sanitized JSON; codes0 success,2 conflict,1 configuration/network/unknown.

Explicit client recovery: accept-handoff requires the exact claim and generation, matching latest handoff target and local slot/session/checkout/host, verifies preserved work scope, then calls authenticated resume (or renew for a submitted claim). It stores the new generation only after the server validates ownership; it never silently adopts authority. Provisional submit/release-acquire may inspect diverged main before integration when no SHA is approved; final-SHA renewal and publication still require current main included and clean exact HEAD. Scope auditing excludes verified upstream commits while checking own commits, two-parent merge resolutions, index, worktree and untracked files; this requires Git 2.36 or later.
