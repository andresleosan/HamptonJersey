# EST-15 · Scoped calculation, local foundation

Base: `7485ff9a1fa8d22ef2bd5a2d758d3a64ac862b75`. This is a pure, disconnected calculation with synthetic tests, not completion, integration, publication or activation of EST-15.

`resolveScopedUnavailability` accepts a complete bounded array of declarations and an explicit as-of time. It snapshots own data properties and rejects accessors, nonordinary prototypes, malformed declarations, incomplete arrays and descriptor errors. This protects its calculation against changing getters; it does not authenticate the caller or make a hostile proxy trustworthy.

A property-wide negative applies to its descendant operations, advertisers and publications; an operation-wide negative applies only within that operation, and an advertiser-wide negative only within that advertiser. A publication scope requires both operation and advertiser. A narrow negative does not purport to decide an entire broader scope: callers must evaluate each actual target, and `not_confirmed` never permits an action. A dated human negative with reason and evidence reference yields `blocked`. Any later or simultaneous human available declaration or visible/modified web observation requires review and does not remove that block. A late-arriving older observation cannot reactivate it. Missing or failed web observations are not negatives. A positive alone yields `not_confirmed`; there is no reactivation operation in this calculation. Inputs are declarations, not proof of their authenticity, completeness or authority.

Validation: adversarial tests were run first and failed on broad scope, contradictory confirmations and accessors; after correction, `node --test tests/server/est-15-scoped-unavailability.test.mjs tests/server/property-facts.test.mjs` passed 23 tests on synthetic data. No browser, D1, network, real source, personal data or notification was used. The full suite was not run in this scoped work.

Before connection, establish authenticated actor and provenance, evidence ownership and retention, authorized scope, trusted and complete facts, version/concurrency rules and a durable atomic fact/event/outbox transaction. A reactivation needs an explicit authorized human act, reviewed new evidence and version/CAS; none is implemented here. Reconcile hierarchy and identity with the authoritative models, then implement and verify action-time enforcement, paginated idempotent propagation, human review, trash integration and recovery before activation. This function does not persist a fact, verify evidence, update projections, create tasks, control retention or block existing routes. EST-15 remains open.
