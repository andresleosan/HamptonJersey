# PUB-06 · Precio por superficie

El editor muestra un cálculo informativo con el precio y la superficie interior introducidos. La operación usa la base actual de venta o alquiler, mantiene moneda y periodo y no suma ni recupera el premium histórico. Un importe, moneda, área, tenencia comercial o periodo de alquiler no válidos o desconocidos dejan el cálculo como no disponible. El redondeo monetario usa los dígitos decimales y la superficie admite desde 0,01 pies² con hasta dos decimales. La validación de guardado comparte esa regla y conserva un valor histórico inválido si no se modifica. Un valor positivo inferior a un penique por pie cuadrado se muestra como inferior a ese umbral en vez de redondearse a cero. El cálculo no se guarda y no modifica el campo de texto manual existente, que continúa tal como está; tampoco añade un nuevo dato a la proyección pública. El texto manual ya aparecía en la ficha pública antes de este cambio.

Las pruebas unitarias cubren venta, alquiler mensual y anual, tenencia comercial, entradas desconocidas o inválidas, precisión y conservación de originales. Tras la corrección, la batería integrada pasó 1.631 pruebas Node y 25 Python; build y check:release pasaron. El navegador local aislado verificó a 1280/390 la actualización al editar, el nombre accesible, la falta de superficie y tenencia, el redondeo, la persistencia del texto manual y la base de precio comercial. No se consultaron fichas reales ni se verificó el panel de producción.

PUB-06 sigue parcial. La [conciliación anterior](reconciliacion-2026-11-13.md) mantiene la discrepancia entre el criterio de premium y el código publicado; el cambio actual no restaura ese campo. Los gastos auxiliares siguen guardados como texto y el cálculo informativo no acredita por sí solo todos los criterios de datos económicos estructurados del plan. Una revisión independiente detectó los casos de precisión y tenencia corregidos en la pasada posterior; también señaló que el texto manual ya era público.
