# PRE-10 · Oposición manual y versión de contacto

13-nov-2026. Base local `1eed9a1c3fb31549403c68b3745d234525f12d6a`; entrega para integración y revisión independiente. PRE-10 continúa **parcial**. No se ha consultado producción, activado un canal, cambiado una política legal ni ejecutado una migración remota.

La ficha permite registrar una oposición para el contacto compartido cuando existe un opt-in. Explica que afecta a todas sus búsquedas, pide confirmación y mantiene el formulario de búsqueda sin guardar. Si hay cambios de contacto pendientes, la acción espera a que se guarden o descarten. Un conflicto exige recargar el contacto y confirmar otra vez; la recarga conserva los campos editados. Errores, navegación y sesión expirada no aplican una respuesta tardía a otra ficha. Un mensaje guardado cuya lectura posterior de historial falla no se presenta como un fallo de la escritura ni invita a repetirla.

Una solicitud de opt-in anterior a la última retirada registrada ya no se ofrece como evidencia de un consentimiento nuevo. Una solicitud posterior puede ser revisada y confirmada por el equipo. Si el historial no se pudo actualizar o identificar, la ficha mantiene cerrada la reconfirmación hasta recargarlo, sin borrar el borrador. Esta guarda usa el orden de eventos existente y no reconstruye consentimientos históricos sin evidencia.

## Corrección del contrato existente

Se reprodujo con fixtures que `updated_at` podía repetirse o retroceder: una retirada y una activación con una versión anterior llegaban a ser aceptadas. También se reprodujo que el registro público repetido podía usar un estado previo de consentimiento, duplicar eventos bajo concurrencia o afectar a un contacto cuyos identificadores habían cambiado antes del batch.

La versión se calcula desde la fila dentro de cada escritura de contacto: para fechas reconocibles avanza al menos un milisegundo, incluso si el reloj se repite o retrocede. Para una versión heredada que SQLite no puede convertir, se conserva el token original y se le añade un sufijo distintivo; no se inventa una fecha histórica. La retirada pública consulta el consentimiento realmente guardado dentro del batch, registra un único evento cuando hay cambio y mantiene el mismo resultado público genérico. Si los identificadores del contacto cambiaron tras la búsqueda, el batch se revierte y devuelve una respuesta genérica de reintento; si se eliminó el contacto, permanece la ruta existente de redacción de eventos.
