# REG-12: restitución del plazo de contacto

Una revisión detectó que la entrega inicial retiró indebidamente el plazo. F0 §5 conserva «We'll be in touch within one working day» como texto editable y §9 identifica el plazo como decisión previa a producción. La propuesta posterior de no prometer un plazo no documenta una decisión de retirar ese compromiso. Se conserva el historial de la entrega inicial y se corrige su conclusión en una nota.

El acuse neutral vuelve a incluir el compromiso de contacto en un día laborable. Es el mismo para altas nuevas, registros repetidos y solicitudes comerciales: no incluye nombre, datos de una cuenta previa, coincidencias, disponibilidad ni afirmaciones sobre progreso de matching. El plazo se refiere al contacto del equipo, no al resultado de una búsqueda.

Antes de la corrección fallaron las dos pruebas puras actualizadas que exigían el plazo; después pasaron 30 pruebas puras de formulario, proyección y presentación. La prueba simulada del formulario comprueba el mismo acuse para las tres situaciones y que no se muestre un marcador sintético de datos anteriores. El E2E se actualizó para exigir el plazo y queda pendiente de ejecución en la integración final. No se consultó D1, se ejecutó navegador ni se verificó producción o la capacidad actual del equipo para cumplir el plazo.
