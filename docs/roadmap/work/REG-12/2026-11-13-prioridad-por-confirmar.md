# REG-12: prioridades históricas en el editor

Base `0148cc8dd3fa4089cf034d9d1c2a55006a3dcd1c`. Este tramo conserva REG-12 **parcial**: no acredita el inicio ni el resultado real de las búsquedas, ni completa EST-01, BUS-01 o BUS-12.

El editor distingue prioridad `unknown`, ausente o no reconocida de Preferred/Off con «Priority to confirm» y dos elecciones explícitas. No presenta un interruptor binario con estado falso. Elegir Must-have o Preferred cambia el formulario; solo Save, tras la confirmación de cambios de criterios ya exigida, guarda. El enlace de revisión enfoca la primera elección. Los interruptores de valores conocidos y las reglas de aplicabilidad y mascotas se conservan. El indicador de respuesta desconocida de un must-have sigue siendo independiente de la prioridad desconocida. No se reparan datos históricos malformados ni se cambia el contrato de API.

Verificación local con datos ficticios: 26 pruebas focales Node pasaron, incluyendo control, foco, requisitos y mascotas. El recorrido `E2E_PRODUCTION_READONLY=0 E2E_SCRIPT=tests/reg12-registration.e2e.cjs npm run test:e2e:isolated` pasó en Chromium en contenedor aislado: conservación de `unknown` al guardar otro campo, foco, elecciones por teclado y ratón y guardado tras confirmación, más reflujo a 390 px con zoom CSS 200 %. No se probó zoom nativo ni WebKit. El primer intento no encontró dependencias enlazadas en el contenedor; el segundo llegó al guardado pero el fixture antiguo no cumplía la confirmación SAP-10. Se copiaron dependencias locales y se ajustó el fixture para confirmar, sin alterar la protección; la ejecución final pasó. Sin producción, datos reales, migraciones remotas ni publicación.

## Corrección de accesibilidad tras revisión

Cuando se elige una prioridad, el foco pasa al interruptor que sustituye a la elección enfocada; cambios externos no capturan el foco. Un error de validación de prioridades marca las opciones, enlaza el mensaje y permite enfocar el primer control habilitado. Las dos opciones se verificaron con teclado a 1280 y 390 px; el error 400 del recorrido se simuló deliberadamente para verificar la respuesta de interfaz, no una incidencia real. El recorrido Chromium aislado pasó con reflujo a 390 px y zoom CSS 200 %. Pasaron 32 pruebas focales Node de foco, presentación, contrato y mascotas. No se ejecutaron WebKit, zoom nativo ni pruebas en producción.
