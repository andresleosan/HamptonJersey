# ANA-03 · Fuente de tráfico de Cloudflare · plan de construcción y activación

**Alcance:** proporcionar en Staff un estado claro y acceso a datos de Web Analytics disponibles, sin atribuir un contacto a una fuente ni vincular navegación individual; ANA-10 cuenta separadamente los QR. Las cifras del proveedor y los contadores D1 no se suman ni se llaman personas únicas. Los informes propietarios y folletos no se incorporan. Construcción desactivada; activación y permisos de cuenta se comprueban en una sesión autorizada.

## Contrato de integración

- [ ] `server/analytics-provider.js`: `getWebTraffic(env,{from,to}) -> {status,source,from,to,as_of,coverage,metrics}`; devolver `{status:'not_configured',metrics:null}` sin valores de cuenta, `{status:'unavailable',metrics:null}` ante permisos, timeout, errores GraphQL (incluidos HTTP 200 con errors), esquema distinto, límites o cobertura no demostrable; nunca convertir fallos a cero. Acotar días 7/30/90 solo si fuente lo soporta; de lo contrario informar ventana disponible, sin rellenar. Habilitar solo via flag y configuración separada. Acceso a `https://api.cloudflare.com/client/v4/graphql` exclusivo servidor mediante secreto almacenado en el mecanismo existente y permiso mínimo de lectura; no exponer token ni hacer llamadas al proveedor desde navegador. Timeout 5s, concurrencia acotada, caché privada en memoria por clave sitio/rango durante 15min y sin persistir datos individuales; no mezclar cuentas ni servir resultados al haber cambiado configuración. No aceptar URL ni query GraphQL libre desde cliente.
- [ ] Consulta concreta candidata para implementación en `server/analytics-provider.js`, como texto fijo y variables estrictamente validadas. El dataset de Web Analytics figura en [Cloudflare](https://developers.cloudflare.com/data-localization/metadata-boundary/graphql-datasets/); la documentación confirma la dimensión de host de referencia, pero **esta consulta y el acceso de la cuenta aún no se han probado**. El constructor verifica por [introspección oficial](https://developers.cloudflare.com/analytics/graphql-api/features/discovery/introspection/) tipo del filtro y nombres en la cuenta autorizada antes de activar; si la cuenta/esquema no admite este contrato, la UI queda `unavailable`, sin aproximación sustitutiva ni acreditación de integración. Usar `accountTag`, `siteTag`, host exacto canónico y ventana `[start,end)` en UTC calculada desde días de Jersey; el objeto de filtro lo crea el servidor, jamás el cliente. La variable `f` propuesta contiene `siteTag`, `requestHost`, `datetime_geq`, `datetime_lt` y no se comparte con otras cuentas.

```graphql
query HamptonTraffic($account: String!, $f: AccountRumPageloadEventsAdaptiveGroupsFilter_InputObject!) {
  viewer { accounts(filter: {accountTag: $account}) {
    total: rumPageloadEventsAdaptiveGroups(filter: $f, limit: 1) { count avg { sampleInterval } }
    sources: rumPageloadEventsAdaptiveGroups(filter: $f, limit: 101, orderBy: [count_DESC]) {
      count avg { sampleInterval } dimensions { refererHost }
    }
  } }
}
```

- [ ] Interpretar `count` como conteo del dataset con muestreo/cobertura documentados por proveedor, no multiplicar por `sampleInterval` sin semántica acreditada y no llamarlo personas únicas. No inferir `Direct` al faltar referer: rotular `No referrer`. Transformar hasta 100 grupos a categorías cerradas Search/Social/Other/No referrer, sin exponer hosts: catálogo fijo versionado Search=`google.com`, `google.co.uk`, `google.je`, `bing.com`, `duckduckgo.com`, `search.yahoo.com`; Social=`facebook.com`, `fb.com`, `instagram.com`. Coincidir solo dominio exacto o subdominio con límite de punto, IDNA normalizada y sin puerto; rechazar URL/path, dominios inválidos o falsos parecidos. Lista puede ampliarse por versión al construir; nunca identificar personas. No restar categorías para derivar otras ni asegurar que su suma coincide con total pues las consultas pueden tener muestreo diferente; nunca solicitar `refererPath`, `requestPath`, queries, emails ni eventos individuales. Si llegan 101 grupos, marcar resultado de fuentes truncado y no calcular `Other` ni total completo restando; el total separado mantiene su propia cobertura. Validar una sola cuenta y el host exacto del filtro; ninguna fila de otro site se mezcla. Si fuente no está activada, rango supera retención o no se demuestra capacidad, devolver `unavailable`; un array vacío no prueba cobertura completa. Test mock verifica variables y shape exactos, referrer malicioso, 101 grupos, aliases, error HTTP200 y ausencia de datos privados. El dataset y la versión de esquema se revalidan con credenciales disponibles únicamente durante construcción/activación autorizada.
- [ ] Operador comprueba titularidad Hampton, capacidad, permisos mínimos, sitio y exclusión de panel/enlaces privados y aviso PRE-09/13. Registrar en evidencia solo capacidades y versión, sin credenciales ni payload. Contrastar la consulta con dashboard para rango pequeño y revisar muestreo; si falla, mantener flag cerrada. Esta comprobación es requisito de **integración y activación**, no condición para redactar o construir el componente y sus pruebas sintéticas.
- [ ] `GET /admin/insights/web-traffic?days=7|30|90` sesión Staff/no-store expone solo `{status,period,as_of,coverage,page_loads,categories}` donde `categories` contiene claves Search/Social/Other/No referrer con `{count,coverage}` y no contiene hosts; hosts válidos no reconocidos se agrupan en Other si la lista de grupos es completa, sin copiar URL o paths. Si hay 101 grupos, `Other.count=null`, cobertura partial y truncamiento explícito; las categorías conocidas también se rotulan parciales. Cifras pueden ser estimaciones y la suma de categorías no se presupone igual al total. UI `admin/src/Insights.jsx`: `Cloudflare Web Analytics`, explicación de fuente/cobertura y períodos, enlace administrativo fijo al panel Cloudflare, `Not configured`/`Data unavailable` sin zeros ni ranking de personas. Si no hay API autorizada el enlace administrativo y el estado funcionan independientemente; la integración numérica sigue pendiente hasta confirmar capacidad.

## Instrumentación y privacidad

- [ ] Revisar configuración existente con operador sin mostrar secretos ni activar; evitar doble beacon. Documentación [RUM beacon](https://developers.cloudflare.com/speed/observatory/rum-beacon/) indica que se procesan datos del navegador y URL de entrada; no afirmar que el proveedor no recibe IP ni que todo dato es anónimo. Verificar con pruebas de red que beacon no cubre panel, enlaces privados, URLs con tokens/PII ni otros hosts; verificar la inyección automática/SPA y reglas de cuenta sin desactivar controles ni afectar rutas ajenas. Si no se demuestra esa exclusión o aviso/contrato PRE-09/13 y condiciones aplicables, no activar. No habilitar RUM en esta tarea de planificación.
- [ ] Tests sintéticos `tests/server/analytics-provider.test.mjs` y API: sin credencial, no configurado, rango no soportado, GraphQL errors HTTP200, 401/403/429/timeout, dato parcial/muestreado, dos sitios, usuario no autorizado, fuga de token/path/referrer, caducidad de caché y cambio de configuración; sin solicitudes reales en unit tests. UI keyboard, errores y recarga; validación real de cuenta solo en fase de activación. Focales, npm test/build/check:release y e2e UI al construir.

**Estado:** plan de construcción completo, con consulta candidata explícita y fallos definidos. El acceso numérico efectivo y activación externa dependen de verificar consulta/dataset, permisos y privacidad en la cuenta; no declarar cobertura completa ni la tarea activada antes de esa evidencia.
