# ANA-03 · Fuente de tráfico de Cloudflare · plan de construcción y activación

**Alcance:** proporcionar en Staff un estado claro y acceso a datos de Web Analytics disponibles, sin atribuir un contacto a una fuente ni vincular navegación individual; ANA-10 cuenta separadamente los QR. Las cifras del proveedor y los contadores D1 no se suman ni se llaman personas únicas. Los informes propietarios y folletos no se incorporan. Construcción desactivada; activación y permisos de cuenta se comprueban en una sesión autorizada.

## Contrato de integración

- [ ] `server/analytics-provider.js`: `getWebTraffic(env,{from,to}) -> {status,source,from,to,as_of,coverage,metrics}`; devolver `{status:'not_configured',metrics:null}` sin valores de cuenta, `{status:'unavailable',metrics:null}` ante permisos, timeout, errores GraphQL (incluidos HTTP 200 con errors), esquema distinto, límites o cobertura no demostrable; nunca convertir fallos a cero. Acotar días 7/30/90 solo si fuente lo soporta; de lo contrario informar ventana disponible, sin rellenar. Habilitar solo via flag y configuración separada. Acceso a `https://api.cloudflare.com/client/v4/graphql` exclusivo servidor mediante secreto almacenado en el mecanismo existente y permiso mínimo de lectura; no exponer token ni hacer llamadas al proveedor desde navegador. Timeout 5s, concurrencia acotada, caché privada en memoria por clave sitio/rango durante 15min y sin persistir datos individuales; no mezclar cuentas ni servir resultados al haber cambiado configuración. No aceptar URL ni query GraphQL libre desde cliente.
- [ ] Antes de conectar los datos, el operador comprueba cuenta Hampton/autorización de Optimyze, sitio y host correcto, método de instrumentación, límites, disponibilidad, esquema y campos agregados mediante [GraphQL Analytics](https://developers.cloudflare.com/analytics/graphql-api/) y [dimensiones Web Analytics](https://developers.cloudflare.com/web-analytics/data-metrics/dimensions/). Registrar solo capacidades y versión sin credenciales; validar por prueba real permitida el dataset, filtros sitio/host y sumas en rango real. Fijar en el servidor una consulta parametrizada revisada para las dimensiones agregadas permitidas; no solicitar paths, emails, querys, IDs o registros por evento. Si el contrato de cuenta/dataset no permite un resumen correcto de volúmenes y referer host sin datos extra, dejar `unavailable`; no sustituirlo por endpoint de eventos individuales ni inventar cifras. Es un gate técnico concreto: la consulta definitiva depende de introspección autorizada y no se presupone que ya existe. Revisar muestreo y límites; marcar `estimated`/coverage sin asegurar exhaustividad.
- [ ] `GET /admin/insights/web-traffic?days=7|30|90` sesión Staff/no-store expone solo estado, periodos, cantidades agregadas y hosts de referencia sanitizados/allowlist de agrupación; hosts desconocidos agrupar como `Other` sin copiar URL o paths, límite de filas y truncamiento explícito. UI `admin/src/Insights.jsx`: `Cloudflare Web Analytics`, explicación de fuente/cobertura y períodos, enlace administrativo fijo al panel Cloudflare, `Not configured`/`Data unavailable` sin zeros ni ranking de personas. Si no hay API autorizada el enlace administrativo y el estado funcionan independientemente; la integración numérica sigue pendiente hasta confirmar capacidad.

## Instrumentación y privacidad

- [ ] Revisar configuración existente con operador sin mostrar secretos ni activar; evitar doble beacon. Documentación [RUM beacon](https://developers.cloudflare.com/speed/observatory/rum-beacon/) indica que se procesan datos del navegador y URL de entrada; no afirmar que el proveedor no recibe IP ni que todo dato es anónimo. Verificar con pruebas de red que beacon no cubre panel, enlaces privados, URLs con tokens/PII ni otros hosts; verificar la inyección automática/SPA y reglas de cuenta sin desactivar controles ni afectar rutas ajenas. Si no se demuestra esa exclusión o aviso/contrato PRE-09/13 y condiciones aplicables, no activar. No habilitar RUM en esta tarea de planificación.
- [ ] Tests sintéticos `tests/server/analytics-provider.test.mjs` y API: sin credencial, no configurado, rango no soportado, GraphQL errors HTTP200, 401/403/429/timeout, dato parcial/muestreado, dos sitios, usuario no autorizado, fuga de token/path/referrer, caducidad de caché y cambio de configuración; sin solicitudes reales en unit tests. UI keyboard, errores y recarga; validación real de cuenta solo en fase de activación. Focales, npm test/build/check:release y e2e UI al construir.

**Estado:** contrato de componente y gestión construibles. El acceso numérico efectivo y activación externa dependen de verificar el dataset, permisos y privacidad en la cuenta; no declarar cobertura completa ni la tarea activada antes de esa evidencia.
